# W3 — Offline signing: design of record

Status: implemented in `patches/0061-W3-offline-signing.patch` (see the W3
receipt in `docs/plans/WALLET_PLAN.md`). This document is the design of record;
deviations land as edits here.

Gate (WALLET_PLAN row W3): *"air-gapped scenario end-to-end; NC: signature
with a foreign domain → reject"*. The named control is the vector
`verify_foreign_domain`: a signature computed under a foreign (domain-less)
digest must be refused with `error: signature verification failed` (exit 65).

## Workflow

The air-gapped split of the W2 pipeline (D-W2-4 keeps all secrets on the
offline side):

1. **online** `tx-prepare` — build an unsigned transfer, wrap it in a
   deterministic envelope, hand it over USB file or QR frames. No keys needed.
2. **offline** `tx-sign` — open the envelope, bind it to the keystore account
   and chain, sign, wrap the signed tx in an envelope. USB/QR back.
3. **online** `tx-verify` — verify envelope integrity, the Ed25519 signature
   under the fixed AuraLite `tx` domain, the chain binding, and (optionally)
   that the signed tx embeds exactly the unsigned envelope the human approved
   (`--against`). Then `broadcast` (W2) accepts the signed envelope directly.

## Decisions

- **D-W3-1 — envelope format `AURALITE-OFFLINE-V1`.**
  `binary = MAGIC(19) || kind:u8 || u64le(len(body)) || body || BLAKE3(...)`
  where `MAGIC = "AuraLite-OFFLINE-V1"`, `kind` is 0 (unsigned) or 1 (signed),
  the digest covers `MAGIC||kind||len||body`, and `body` is the canonical C2
  encoding of the `UnsignedTx` (kind 0) or the full `Tx` (kind 1). The text
  form (USB file) is unpadded base64url of the binary — one deterministic
  line. The checksum detects corruption; it is **not** authentication (anyone
  can recompute it) — the signature in kind 1 is the authentication.
- **D-W3-2 — QR transport.** Frames `ALO1:{ii}/{nn}:{chunk}` carry the text
  form split into `--qr-size`-char chunks (default 180), one frame per line;
  `qr-split` writes `frame-NNN.txt` files, `qr-join` reassembles and requires
  exactly the index set `0..nn-1` (missing/duplicate/bad frame refuse, exit
  65) and a valid envelope afterwards.
- **D-W3-3 — verification contract (`tx-verify`).** Fixed order: envelope
  decode (fail → `error: envelope: bad encoding`), checksum
  (`error: envelope: checksum mismatch`), kind must be 1
  (`error: envelope: expected signed`), `Tx::from_canonical_bytes`, chain
  binding (`error: foreign chain-id`, exit 65 — the W2 named control
  semantics), signature under the fixed `AuraLite-Crypto/tx-signing-v1` +
  `tx` domain (`error: signature verification failed`, exit 65 — the W3 named
  control), optional `--against` unsigned envelope byte equality
  (`error: unsigned mismatch`, exit 65).
- **D-W3-4 — no new secrets or trust.** `tx-sign` reuses the W2 keystore flow
  (`--keystore`, `--password-file`, `--account`), refuses when the envelope
  signer differs from the keystore account (`error: signer mismatch`, exit 65),
  and `tx-prepare` takes the signer address explicitly (`--from`) so it runs
  keyless on the online machine.

Exit codes are the W2 set: 0 / 64 (usage) / 65 (policy refusal) / 69
(keystore/ledger/crypto failure). Public test data only — never use for funds.

## Test gate

`tests/fixtures/w3_offline_vectors.json` — 24 deterministic cases generated by
the independent oracle `tools/gen_w3_vectors.py` (pure Python: BLAKE3, Ed25519
RFC 8032-checked, C2/C4 encoders, bech32, BIP-39/SLIP-0010) and asserted
byte-for-byte by `tests/w3_offline.rs` (24 vectors + a count guard). Groups:
prepare (4), sign (5), verify (6), qr (5), air-gapped end-to-end (4).

Mutation controls (`tools/nc_w3.py`, 6): foreign-domain signature accepted
(named control → `verify_foreign_domain`), envelope checksum skipped →
`sign_bad_checksum`, signer binding dropped → `sign_signer_mismatch`, QR gap
accepted → `qr_missing_chunk`, QR duplicate accepted → `qr_duplicate_chunk`,
`--against` comparison skipped → `verify_against_mismatch`.
