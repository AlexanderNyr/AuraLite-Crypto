## 3. What is explicitly NOT real

- **No network.** No P2P, no consensus loop, no validator set running, no
  blocks produced, no RPC, no node binary.
- **No state tree.** `state_root` is a caller-supplied `Hash` in C5; C7 fixes
  only key/account layout; C8 computes an allocation commitment, not a JMT
  root. `STATE_PLAN` S1–S7 owes the tree, proofs, persistence and snapshots.
- **No VM or execution.** `aura-exec` is an empty placeholder. `wasmtime` is
  not a dependency.
- **No wallet, explorer, contracts, bridge, DeFi, stablecoin, token market.**
  Stage 1 issues no market token by decision Q5.
- **No external audit, no white paper, no mainnet.** ⏸ Stage 2, by separate
  decision. MiCA notification requirements were noted in `ROADMAP.md`.
- **No sanitizers or 24-hour fuzzing.** C9 delivered four libFuzzer source
  targets and a 60-second portable gate; H3 owes Miri/ASan/UBSan, coverage
  and the long campaign.
- **No `cargo deny`.** The dependency gate checks exact pins, crates.io
  sources, sha256 checksums and allowlist drift — but not licences or
  advisories (H1).
- **No determinism gate for state root** (X7) and no benchmark numbers (P
  phases).

## 4. Known weaknesses (deliberate, documented)

1. `serde_json` is used for genesis config parsing — allowed by
   `ARCHITECTURE.md` for configs only, never for consensus bytes. There is no
   `serde` derive in any crate.
2. Ed25519 public keys travel inside each tx signature envelope because
   Ed25519 cannot recover a key from a signature; an on-chain key registry
   does not exist yet (C7/S1).
3. `qc`, `state_root` and (before C8) `validator_set_hash` are opaque or
   caller-supplied values. C8 now computes the validator-set hash; the rest
   await B/S phases.
4. The portable fuzz harness is not coverage-guided. It is a deterministic
   totality/panic gate; H3's libFuzzer campaign provides coverage.
5. Crypto dependencies are pinned and checksummed but not licence/advisory
   scanned. `cargo deny` is an explicit H1 debt.
6. Rust toolchain verification in this sandbox used
   `RUSTUP_TOOLCHAIN=stable` (rustc 1.99.1) because the pinned-channel
   download hit a tmpfs size limit; CI installs the pinned 1.99.1 directly.

## 5. Verdict

**L1 — Core libraries + test rig, no network.** `CORE_PLAN` C0–C10 is
complete and auditable. Milestone M0 is **not** complete: it also needs
`STATE_PLAN` S0–S2 and `EXEC_PLAN` X0–X2. Starting the next plan is the
correct next action; claiming a blockchain would not be.
