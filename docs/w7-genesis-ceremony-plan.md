# W7 genesis ceremony — design of record (D-W7-1..D-W7-5)

**Phase:** W7 (WALLET_PLAN Stage 2). **Deliverable:** `patches/0102-W7-…`.
**Model:** `docs/w6-web-wallet-plan.md` (W6). The ceremony is an offline,
deterministic workflow run on air-gapped machines: keys are generated from
ceremony entropy, split with Shamir sharing, witnessed by a hash-chained log,
and every temporary byte is destroyed before the genesis is sealed.
Implementation: `crates/aura-genesis/src/ceremony.rs` (module + CLI driver),
`src/bin/aura-ceremony.rs`. PUBLIC TEST DATA ONLY — never use for funds.

## Problem

A genesis ceremony is where the master keys of a chain are born. Real
failures: key material left on the ceremony laptop (later imaged into CI or
the repository), a recovery scheme nobody can actually recover from, a
"ceremony log" that does not prove anything, and a sealed genesis whose
validator set is not the one the witnesses saw.

## Decisions

- **D-W7-1 (offline generation).** Validator consensus keys are derived
  deterministically from ceremony entropy (`BLAKE3(KEY_CONTEXT || entropy ||
  i)`, Ed25519), one entropy file per ceremony on an air-gapped host. Secrets
  live only in `media/` files until destruction; only public keys, addresses
  and powers enter the manifest and the genesis.
- **D-W7-2 (Shamir sharing).** Every secret is split into `K` shares with
  quorum `T` (Shamir over GF(2^8) with polynomial `0x11b`, exp/log tables
  generated by 3, per byte, deterministic coefficients
  `BLAKE3(SHARE_CONTEXT || secret || i || byte)`). Any `T` distinct shares
  reconstruct exactly (scenario-pinned commitments); fewer than `T` are
  refused, duplicate share coordinates are refused. Shares are delivered
  material — they never contain the full secret and are not flagged by the
  scan.
- **D-W7-3 (witness logs).** Every step appends one entry to
  `witness.log`, hash-chained (`h_i = BLAKE3(WITNESS_CONTEXT || h_{i-1} ||
  entry)`); the tip is printed. Verification recomputes the chain — any
  edit/insertion/deletion is `witness chain broken`; a missing step is
  `witness log incomplete`. The `generate` entries commit to the pubkey set.
- **D-W7-4 (destruction of temporary media).** `shred` overwrites every
  `media/` file twice (0x00, then 0xFF) and removes it; `seal` refuses while
  any temporary media exists (`temporary media present`).
- **D-W7-5 (the O5 gate).** `seal` builds the canonical `Genesis` from the
  witnessed pubkey set and the recorded parameters and refuses a manifest
  that disagrees with the witnessed keys (`validator set mismatch`); the
  sealed `genesis` hash and `validator_set` hash are printed and witnessed.
  `verify` re-runs the chain/completeness checks and scans the ceremony
  outputs and a chosen root for private material (`media/` files, `secret=`
  lines): `scan=clean` or `private material found: <path>` — "not one private
  key in the repository/CI".
