# W2 — `aura-wallet` CLI

Status: ACTIVE (phase patch `patches/0060-W2-*`). WALLET_PLAN row W2: the `aura-wallet`
CLI with `new/import/list/balance/transfer/sign/broadcast/stake/vote`; test gate =
**40 CLI vectors, including rejection of a tx with a foreign chain-id**. Depends on
CORE C1-C4 (addresses/signatures) and the NODE D4 tx pipeline. Builds on W1 (keystore
v2, `W1-FORMAT-v1` frozen) and W0 (exposure rules).

## 1. Scope

| Command | What it does | Chain artifacts |
|---|---|---|
| `new` | Generate a BIP-39 mnemonic (24 words, optional `--entropy-file` for deterministic runs), derive account 0 (testnet path `m/44'/1'/0'/0'/0'`), write a keystore v2 (Argon2id + AES-256-GCM). | keystore file |
| `import` | Same from an existing mnemonic (`--mnemonic-file`), with the recovery-metadata verification path (reduced mnemonic accepted ONLY with `--accept-reduced-mnemonic`). | keystore file |
| `list` | List keystore entries: index, path, address, public key. Never prints secrets. | - |
| `balance` | Read the account balance from the ledger. | - |
| `transfer` | Build + sign a `TxKind::Transfer` tx (nonce from ledger), print `txid` + hex. | signed tx |
| `sign` | Sign an unsigned tx (hex/file): **rejects a tx whose embedded chain-id differs from the wallet chain** (the W2 named NC). | signed tx |
| `broadcast` | Verify chain binding + signature, append the tx to the ledger, print `txid`. | ledger append |
| `stake` | Build + sign `TxKind::Delegate` / `Undelegate` with the canonical `wallet-stake-v1` payload. | signed tx |
| `vote` | Sign a **governance ballot** (`wallet-ballot-v1`, Ed25519, chain-bound) + `vote --verify-ballot` to check one. | ballot document |

## 2. Decisions (recorded, reversible only with a plan edit)

- **D-W2-1 (ledger backend).** W2 commands that need chain state (`balance`, nonces,
  `broadcast`) run against a **file ledger** (`--ledger <path>`, JSON: chain-id,
  per-address balance/nonce, appended txs). Rationale: the dependency set has the D4
  RPC *server* (`aura-rpc`), not an HTTP client; the 40-vector gate is offline and
  deterministic. An HTTP JSON-RPC client transport rides with the future transport
  work and slots in behind the same `Ledger` trait. The chain-id binding and
  signature checks are identical for every backend.
- **D-W2-2 (`vote` semantics).** B9 governance votes are **BLS12-381 validator
  signatures** (`GovernanceVote`, `Domain::Vote`); the frozen `W1-FORMAT-v1` keystore
  holds Ed25519 seeds only. `vote` therefore signs a wallet-level **ballot document**
  (Ed25519 over `AuraLite-Crypto/wallet-ballot-v1 || chain || proposal || voter ||
  choice || height`), a verifiable intent a validator/governance tool can collect.
  BLS key material would be a new keystore version (explicitly out of W2 scope).
- **D-W2-3 (payload formats).** `stake` payloads use the wallet-canonical encoding
  `AuraLite-Crypto/wallet-stake-v1 || action-tag || validator-address || LE amount`
  (tag 0 = delegate, 1 = undelegate). The tx layer treats payloads as opaque
  (length-prefixed); the encoding is pinned by the W2 vectors.
- **D-W2-4 (secrets policy).** Passwords and mnemonics enter via `--password-file` /
  `--mnemonic-file` / `--entropy-file` (W0 T-W0-2: never as argv values). Mnemonics
  are printed **once** on `new` (with the PUBLIC TEST DATA notice in test fixtures)
  and never to logs; all secret buffers are `zeroize`d.

## 3. Exit codes and error taxonomy (deterministic)

| Code | Meaning |
|---|---|
| 0 | success |
| 64 | usage error (`error: usage: ...`) |
| 65 | policy refusal: `error: foreign chain-id: tx=<found>, wallet=<expected>`, `error: bad password`, `error: reduced mnemonic refused`, ... |
| 69 | ledger/node failure (`error: ledger: ...`, unknown address, insufficient funds, broadcast rejected) |

## 4. Test gate: 40 CLI vectors

`tests/fixtures/w2_cli_vectors.json` (generated by `tools/gen_w2_vectors.py`,
asserted by `tests/w2_cli.rs`): each vector pins argv, fixture files (keystore,
ledger, password/mnemonic/entropy), expected exit code and expected stdout/stderr
lines. Coverage sketch (40):

- `new` x 5 (deterministic entropy, account indexes, password round-trip, output
  shape, wrong-password refusal at decrypt),
- `import` x 5 (standard mnemonic, reduced+flag, reduced without flag -> refuse,
  NFKD/NFC profiles, address derivation match),
- `list` x 3 (one entry, two entries, empty keystore -> usage/empty),
- `balance` x 4 (known balance, unknown address -> 69, ledger chain mismatch -> 65,
  parse order independence),
- `transfer` x 6 (happy path txid match, nonce sequencing, insufficient funds -> 69,
  bad password -> 65, tip > max_fee -> 64/refused, payload byte-exact match),
- `sign` x 6 (happy path byte-exact, **foreign chain-id tx -> 65**, foreign chain in
  ledger+wallet agree, already-signed -> refuse, unknown signer -> refuse, signature
  verifies against pinned pubkey),
- `broadcast` x 4 (append+txid, bad signature -> refuse, foreign chain-id -> 65,
  expiry in the past -> refuse),
- `stake` x 4 (delegate byte-exact, undelegate byte-exact, unknown validator ->
  refused, amount=0 -> usage),
- `vote` x 3 (ballot byte-exact + verify, ballot for foreign chain -> 65 on verify,
  bad choice -> usage).

## 5. Negative controls (tools/nc_w2.py, model of nc_w1.py)

- `NC: foreign chain-id accepted -> gate red` (drop the chain check in `sign`),
- `NC: ballot chain binding dropped -> gate red`,
- `NC: password echoed in output -> gate red` (leak a secret into stdout),
- `NC: signature verification skipped on broadcast -> gate red`,
- `NC: stake payload encoding nondeterministic -> gate red` (inject map-order bytes),
- `NC: nonce replay accepted -> gate red`.
